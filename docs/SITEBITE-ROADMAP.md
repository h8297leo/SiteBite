# SiteBite 開發路線圖

目前版本：v0.3.0-public-web。當前工作僅為 Phase 2.1；後續階段須等待使用者指示。

- GitHub：https://github.com/h8297leo/SiteBite
- Render：https://sitebite-1.onrender.com/

## SiteBite 核心定位

全球即時公開網路美食與景點探索引擎。

使用者輸入任意城市、地名、地址、景點或 GPS 座標，程式即時搜尋公開網路，擷取真實地點，驗證後依距離排序。

## 核心原則

1. 不建立永久店家或景點資料庫。
2. 不預先建立任何城市的店家清單。
3. 不寫死特定地點或測試結果。
4. 不要求使用者提供 Google 或其他商業搜尋 API Key。
5. 搜尋時直接取得公開網路資訊。
6. 允許短期快取，但不得將快取轉為永久POI資料庫。
7. 美食與景點使用獨立搜尋流程。
8. 全球多語言搜尋。
9. 最多50筆結果，每頁10筆。
10. 預設距離由近到遠。
11. 保留地圖、導航、GPS及來源證據。
12. 不虛構店家、座標、營業時間、評分或評論。
13. 不繞過網站登入、CAPTCHA、robots或存取限制。
14. 不因資料不足而用假資料填滿50筆。
15. 保留GitHub與Render公開部署架構。

## Phase 2.1：公開搜尋可靠性

改善現有搜尋引擎在公開環境出現0筆結果的問題。

工作重點：

- 搜尋來源錯誤隔離。
- 公開來源失敗時的備援。
- 合理逾時與請求控制。
- 避免來源成功但候選被錯誤排除。
- 區分來源失敗、候選不足、分類不符與真正沒有結果。
- 保留現有搜尋診斷。
- 避免過度依賴單一來源。
- 保留原有地理驗證與去重。
- 不新增永久POI資料庫。

僅修正現有程式可確認的缺陷；無法確認的問題回報所需診斷，不猜測或大量改寫。實際功能由使用者在Render驗收；開發驗證限於TypeScript、建置、正式啟動、健康檢查及直接相關單元測試，不大量呼叫公開來源。

## Phase 2.2：分類搜尋系統

### 美食第一層：用餐時段

全部、早餐、早午餐、午餐、下午茶、晚餐、宵夜、24小時。

### 美食第二層：店家類型

全部、餐廳、小吃、咖啡廳、甜點、麵包烘焙、飲料茶飲、速食、自助餐、酒吧餐酒館。

兩層可以交叉搜尋，例如：

- 早餐＋小吃
- 下午茶＋咖啡廳
- 下午茶＋甜點
- 宵夜＋小吃
- 晚餐＋餐廳

分類必須直接參與搜尋查詢生成，而不只是前端篩選。若來源無法證明營業時間或類別，不得虛構。

### 景點分類

全部景點、自然景觀、公園步道、歷史古蹟、文化藝術、博物館、展覽活動、地標建築、拍照景點、親子景點、商圈老街、夜景景點、宗教景點、秘境探索。

景點與美食必須維持獨立搜尋流程。本階段僅規劃，Phase 2.1不實作上述新增分類。

## Phase 2.3：公開搜尋來源擴充

目標是降低對Overpass的依賴。

參考成熟開源專案的搜尋架構：

- OsmAPP
- Nominatim
- SearXNG
- Overpass API
- OpenStreetMap分類標準

擴充方向：

- 多語言搜尋查詢。
- 合法公開網頁搜尋。
- 地方美食及旅遊網站。
- 官方觀光公開資訊。
- 公開文章場所擷取。
- 地點名稱、地址及座標驗證。
- 跨來源去重與證據整合。

不得假裝已整合實際無法存取的網站。本階段僅規劃，Phase 2.1不進入來源擴充階段。
